To check whether the kernel itself has fallen behind the app, run node scripts/design_kernel_export.mjs --check styles.css in travel-workspace against a copy of the kernel's file.

What the propagation test showed
This project was created bound to the kernel. At creation it held no files and no _ds folder.
The kernel then received styles.css. About twelve minutes later, neither this project nor the bound _ds folder in Vesper — Home had changed, and the kernel's _ds_manifest.json still listed no global CSS.
So a bound folder is a copy, not a live link, and writing files to the kernel does not rebuild its manifest. Reuse here is a versioned copy: styles.css was copied with its stamp, and the stamp is the drift signal.
