below. These are CV-2 acceptance boundaries using existing root forms; the
opening-claim and independent-exploration subset now has connected local tests:

| --- | --- |

Home should express the useful consequence for the person's current horizon;
Places should provide substantive spatial exploration and relevant detail.
Neither needs a new status dashboard. Test emitted content and exact
continuations in ordinary Home and both Places v2 callers, with a varied
portfolio that includes understanding, possibility, social material and
practical help. C/D closes only when actual owner facts alter the appropriate
output while independent value survives. The integration roadmap owns the
implementation sequence and shared assessment contract.

These are receiving expectations for packages A–E, not newly shipped kinds or
permission to activate production. [The three concrete experiences](situated-value-decision-matrix-2026-09-06.md#12-useful-preparation-three-concrete-receiving-experiences)
exercise explanation, ordinary possibility and addressed social preparation.

| Result state | What Home delivers | What must not happen |
| --- | --- | --- |
| Ready and eligible | The substantive comparison, concrete offer or bounded assessment, with exact sources and optional continuation | A label or teaser that makes the person ask again for the actual value |
| Accepted preparation still running | Useful existing material, such as the original friend note; explicit progress belongs where the person is relying on requested work | Speculative-job spinners, an implied completed assessment, or an internal work queue replacing the Home portfolio |
| Unsupported, failed or expired | Remaining valid material with the consequential limitation; withdraw invalid fit claims and report failure for work the person entrusted to Vesper | Asking the friend to become a researcher, silently dropping an accepted task, or portraying the fallback as equivalent completed service |

On completion, revalidate source/use/audience scope and consequential facts
before admitting the result. Preserve scroll, selected identity and touch
targets; define stable in-session arrival through existing delivery/invalidation
seams, or receive on a later appropriate read. This is a design requirement,
not certification of an automatic in-session update path. A completed refresh
is not necessarily a new card or push; changed validity and changed prominence
are separate decisions. Revoked or obsolete claims must not remain visible
merely to preserve layout continuity.

Ordinary GETs, tab focus and app launch do not enqueue production. The
[accepted worker decision](../decisions/2026-09-06-bound-source-production-worker.md)
owns permitted triggers and activation gates. Integration supplies supported
production/delivery paths; Home consumes them without another generator.
For each specimen record the real source, supported producer/read, exact
renderer and destination, trigger if new work is needed, and readiness gap.
Measure total checking and repair effort across recipients and organizers,
alongside latency, reuse and cost. Written specimens and fictional supply are
design evidence, not runtime or real-world availability receipts.

## 6. Production classification and generation policy

| Value type | Default treatment | Refresh trigger | Degraded fallback |
| --- | --- | --- | --- |

### 8.2 Findings that determine the work

1. **Serving is connected; supply is not complete.**
   `read_prepared_source_contribution` is read-only and returns at most one
   eligible private result. Searches for `build_source_contribution_work_item`
   and `create_source_contribution_workflow` under `backend/` found definitions,
   not runtime callers. Private serving cannot substitute for reusable public
   knowledge or an authorized request binding.
2. **Home's contextual adapter reduces much of the available richness.**
   `home_candidates_from_contextual_places` takes at most two qualifying cards
   in feed traversal order. `ANGLE` retains its preview; Place/Experience/Area/
   City become `RootLink(label, relation, target)`. Trace decisive supplied facts
   before inventing another kind or increasing this cap. Arrival of more
   candidates alone will not make an event's useful details visible.
3. **The default portfolio does not contain a dedicated retained-ticket read.**
   It reads graph state, legacy trips, proposals, context, saves, receipts,
   addressed handoffs and contextual Places. Source discovery can supply eligible
   material but does not establish a complete confirmation/pass projection.
   Reuse the retained-evidence adapter contract and canonical Source readers.
4. **Page policy can constrain the visible value.**
   `selectors.py` gives Quiet orientation the dominant position, allows one
   in-motion row and uses posture-based cumulative attention budgets. These
   are existing decisions/heuristics, not evidence that additional valid value
   should never appear. Record where candidates are lost before changing them.
   Preserve accepted demand and priority rules unless explicitly amended.
5. **Some presentation still describes machinery.**
   `HomeRootV2UnitRenderer` renders a raw semantic-kind stamp for compositions,
   generic instrument headings and generic continuation doors. These are
   concrete receiving defects to assess against actual payloads, independent
   of another visual redesign. Do not invent facts to improve the headings.
6. **Exact subject is not exact source context.**
   Dossier/entity navigation and contextual Ask are repaired for supported
   subjects. A `place_handoff` ref accompanies the venue but is not carried
   through a certified original/depth/Ask path. Source/passage/revision context
   requires its own current-authority receiving contract, not a raw-text URL.
7. **Expiry is correct at a coarse display boundary.**
   The mobile expiry hook invalidates the current root presentation. It does
   not establish stable per-unit arrivals or replacements. Preserve this safe
   behavior while specifying a minimal improvement through existing hooks.
8. **The test boundary must change.**
   The four-family test stops before common value judgment. The current
   `HomeRootExperience` suite mocks `HomeRootV2Screen`, so it checks orchestration,
   not the actual full scroll. Keep those tests and add connected output and
   real-renderer coverage; do not rename their existing passes as journey proof.
