# Interaction Kernel — useful arrangements with less machinery

## Assignment

Continue the existing `/Users/feihuyan/Downloads/vesper-interaction-kernel-lab`
project. Use it to design concrete, lightweight coordination and practical-help
experiences. Do not build production features, retire services, or invent a

continuity. A person should not have to maintain a plan to receive useful help.

## Work package A — intention without compulsory planning

Start from “Maybe jazz Saturday” and “Keep that option; don't build around it.”
Deliver useful possibilities before creating or naming a Plan. Explore retaining
an intention without a named container, explicitly marked as a product proposal.
Remembering, structure, and obligation remain independent.

Show the complete arrangement as it becomes useful: optional jazz, fixed dinner,
and a feasible way between them. Then exercise a direct time adjustment, “make it
less rushed,” removing one option, re-entry after unrelated chat, and Undo.

Recommend where **current state rests**. A card may remain message-light while
also being directly inspectable from Home/Life. Do not presume a chat transcript
is the only destination, or that a full itinerary editor is the alternative.
Show that the person can inspect the arrangement without asking what is current.

Do not run a new exhaustive modality experiment. Use existing lab learnings to
recommend a coherent combination: direct controls for obvious local adjustments,
language for expressive changes, and an appropriate preview for material effects.
Record remaining usability hypotheses honestly.

## Work package B — an ordinary shared evening

Reuse the existing host, thin guest, and contributor scenario. Include:

- a host naturally initiating dinner;
- a guest opening a bounded link and getting value before being asked;
- a recommendation or “I'll bring dessert” contribution without task creation;
- one consequential shared change and the affected person's later view;
- independent optional activities before/after the shared portion;
- someone ignoring an optional contribution request without public pressure.

Keep the existing Plan/Occasion distinction. A shared core need not absorb each
person's entire evening. One decision owner need not imply a mandatory navigation
jump: explore mounting the same authorized action where its context is visible,
without creating independent competing decision cards or authorities.

## Work package C — external reservation, integrated experience

The design target is **no Vesper checkout, payment submission, hold, provider call,
cancel/rebook execution, or automatic merchant transaction**. This is the founder's
contraction direction, not a claim that existing infrastructure has been retired.

Draw: useful option → provider link → leave Vesper → return → confirmation supplied
or not supplied → useful Home/arrangement readback. Opening a link is not a booking;
returning from a provider is not confirmation. Show how forwarding a confirmation
can be enough without a completion wizard or automatic inbox access.

Also draw a changed reservation: Vesper can explain relevant evidence and help
adapt the evening, while the actual merchant change remains external. No success
claim or monitoring promise without a supporting, explicitly scoped capability.
Prefer an ordinary dinner as the primary case; a flight is an additional stress
case, not the only demonstration of practical competence.

## Work package D — expense help without an expense mini-app

Compose three jobs separately:

1. A receipt attached to a question: explain the charge; no automatic debt.
2. “I paid $126 for dinner; split it between me, Maya, and Theo”: show the
   resolved parties and $42 shares, with the appropriate shared-effect boundary.
3. “Theo only had a drink” or “Maya already paid me”: request only the missing
   consequential detail and show exactly what the correction changes.

AI interprets and reduces input burden. Deterministic code remains responsible
for arithmetic, ledger truth, and settlement. A photo does not establish payer,
participants, sharing authority, repayment, or currency conversion. Do not make
all trip members the invisible default. No external money movement is in scope.

Keep inspectable detail and correction accessible without reproducing a category
form suite, balances dashboard, or mandatory review queue. Distinguish private
recording from telling others they owe money. Include an ordinary non-Trip dinner.
