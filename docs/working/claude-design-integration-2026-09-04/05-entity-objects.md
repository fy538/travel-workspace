## Work package A — one place, several legitimate entry contexts

Use one canonical place and compose arrival from:

- Home's current possibility;
- Places search/map/exploration;
- a friend's addressed recommendation;
- Life's saved material or accumulated relationship;
- an arrangement where the place is already relevant.

Keep its identity consistent. Allow facts and authorized context to vary without
inventing a different entity. Show what the incoming context changes, what it
does not change, and exactly where Back returns. Opening must not imply saving,
attendance, liking, research authorization, or a shared consequence.

## Work package B — intent beyond a live Tonight Occasion

The selected page offers “Tonight?” only when a live Occasion exists. This is a
useful bounded action, but ordinary prospective intent needs a design answer too.

Exercise three situations:

1. “Keep this place” with no intended date or gathering.
2. “Keep it as an option for next Saturday; don't build around it.”
3. “Would this work for Maya's dinner?” with an existing shared arrangement.

The second is not necessarily a new named Plan; the third is not an accepted
shared choice. Explore the smallest contextual mechanism, possibly an existing
action plus language, rather than restoring the Trip → day → review ladder.
Do not add all three as permanent buttons.

Also show two potentially relevant arrangements. Avoid silently picking one or
placing a universal Plan picker in front of every action. If a choice materially
changes consequences, a small contextual clarification may be necessary.

## Work package C — Places and Life are not duplicate detail pages

Reconcile older Places Focus boards with the selected entity composition.
Those boards use separate fact/personal/social lanes; this page favors short
paragraphs and inline citations. Preserve source and author distinctions without
forcing every lane into a permanent visual section or building a second detail
renderer. A deliberate exception should be named, not introduced accidentally.

Distinguish “the place itself” from “my history and relationship with this place.”
Life can expose accumulated episodes and material; the entity page can expose a
small relevant relationship read and a clear way into the fuller record.
Do not pull the entire Life dossier into the page. Coordinate labels and return
behavior with the Life handoff.

## Work package D — useful practical edges without booking ownership

Keep Directions and a genuine external Reserve link where supported. Show the
handoff clearly enough to avoid implying Vesper performs the reservation.
Returning to the page without evidence must not mark it booked. Supplied
confirmation belongs to its existing source/arrangement owner; the page projects
the relevant result rather than becoming a merchant workflow.

Reuse the existing face-opened attributed contribution. Retaining the place,
retaining a permitted copy of someone's words, and sending it onward are distinct
effects. Keep the primary path light; use existing bounded sheets where needed.

## Deliverables and review bar

Return a small set of connected entry/action/return screens, a compact context
matrix, and exact proposals for any changed verbs or navigation. Include the
no-Occasion, no-personal-history, and thin-source cases. Preserve sparse pages
without adding generated filler or a mandatory research prompt.

List reused components and any changed data needs; distinguish implemented,
design-only, and unresolved behavior using refreshed evidence. No seed/backfill,
provider research, permission expansion, production code changes, or new entity
kinds are authorized by this brief.

Success means the same place remains recognizable, the person can express a
useful future relationship without planning ceremony, and every doorway returns
to the right context. The entity lane should continue independently where these
interfaces do not affect its existing implementation work.
