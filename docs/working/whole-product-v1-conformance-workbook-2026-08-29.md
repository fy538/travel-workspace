# Whole-Product V1 Conformance Workbook

## Decision and purpose

Vesper will define and build the next product as one four-root lived-world
system, not as a collection of feature proofs and not as one behavior loop
allowed to define the architecture.

The governing product moves are:

> **Make sense. Open possibility. Help it work. Carry forward.**

The governing surface law is:

> **Chat receives and operates. Home and Places return value. Life preserves
> and organizes. Canonical owners and the consequence engine connect all
> four.**

This workbook is the bridge from those principles to comparable experiences,
surface requirements, owner boundaries, capability work, and implementation
gates. It is not a shipped-behavior claim, a visual specification, or a
dogfood plan.

## Wave 0 closure status

**Closed on 2026-08-29.** The eighteen-case portfolio and the product rulings
in section 11 were accepted through the [Wave 0 closure
decision](../decisions/2026-08-29-close-whole-product-v1-wave-0.md).

The closure accepts the four-root target navigation direction while leaving
detailed visual composition experimental. It also corrects three portfolio
boundaries:

- an attached item may still be an Ask/T0; deliberate Bring/T1 requires clear
  custody, scope, and reversible source-bound continuity;
- asynchronous social value remains governed by Source authorship, audience
  grant, Place, Occasion, and accepted consequences—there is no new universal
  social owner; and
- A18 proves causal later reuse without requiring every contribution to pass
  through all four roots.

## 1. Program posture

### 1.1 What is frozen now

The following are accepted target-product constraints:

- four roots: Home, Chat, Places, and Life;
- four recursive, non-mandatory product moves;
- one dominant job per unit and several moves per root;
- one durable owner per consequence;
- one object identity across root projections;
- immediate value before classification, reflection, or organization work;
- Chat as contribution surface and cross-owner agentic interface;
- Home and Places as substantial value-return surfaces;
- Life as governed continuity, re-finding, and organization;
- multiplayer as a cross-cutting condition rather than a fifth root;
- the five independent contribution-authority axes: Use, Retention,
  Inference, Audience, and Action;
- generated interpretation is not lived truth;
- correction, revocation, and causal invalidation are product behavior; and
- silence, answer-only, and ephemeral composition are valid terminal states.

### 1.2 What remains deliberately unfrozen

- exact Home and Places composition;
- exact card, row, map, timeline, article, audio, or instrument treatments;
- navigation animation and detailed visual hierarchy;
- ranking weights and page density;
- the final naming of several user-facing lenses;
- which generated compositions earn saved identity;
- which existing Trip-specialized handlers remain permanent infrastructure;
- runtime activation of the agentic semantic facade; and
- product-behavior dogfooding.

The root system is accepted as target direction. Its visual anatomy remains a
design variable. Those are compatible positions and should no longer be
described as a contradiction.

### 1.3 Current execution rule

The current agentic facade remains off at runtime. Its contracts, compiler,
semantic catalog, owner reader, and fixtures serve as an **offline conformance
harness**. Unstable product surfaces cannot produce trustworthy dogfood
evidence about the new product.

### 1.4 Verified implementation baseline

The backend branch `feature/agentic-semantic-facade` contains the complete
eight-commit facade package through `a9a40d6ab`. Focused verification on
2026-08-29 passed **96 tests**. `CONCIERGE_AGENTIC_FACADE_MODE` defaults to
`off`; with the flag off, the package cannot change prompts, served tools,
execution, or user output.

The target semantic catalog currently reports:

| Readiness | Count | Interpretation |
| --- | ---: | --- |
| mapped | 4 | target semantic read maps honestly to current capability |
| partial | 18 | useful substrate exists, but owner or semantics are incomplete |
| unavailable | 2 | no honest current capability |
| **total** | **24** | descriptive catalog only; not model-visible serving |

Compatibility presently uses eleven legacy-tool paths, nine runtime-context
paths, two existing-owner readers, and two explicit missing paths. This is a
healthy architectural baseline because it exposes the gap instead of hiding it
behind generated prose.

## 2. Whole-product evaluation grammar

Every representative experience must answer all of the following without
hand-waving:

| Dimension | Required answer |
| --- | --- |
| Human situation | What is happening in the person's life, not only in the UI? |
| Existing context | What does Vesper know, from which Sources, under which scope and freshness? |
| Entry | Which root or object begins the experience, and what selection travels with it? |
| Immediate return | What value arrives before the person performs organization or reflection work? |
| Product move | Which of the four moves is dominant, and which are supporting? |
| Root sequence | Which root owns each part of the experience and why? |
| Owner | Which domain owns durable truth or consequence? |
| Agency phase | Is Vesper inspecting, composing, proposing, committing, monitoring, or reconciling? |
| Authority | What are the Use, Retention, Inference, Audience, and Action bounds? |
| Multiplayer | Whose evidence, welfare, authorship, participation, and authority are involved? |
| Medium | Which medium makes the important relation easiest to perceive? |
| Consequence | What changes in product state or the world, if anything? |
| Return | Where does the person land, with which context preserved? |
| Residue | What persists, expires, remains provisional, or is released? |
| Repair | How do correction, Undo, revocation, partial success, and stale truth behave? |
| Stopping rule | Can the answer end on view or remain silent without creating debt? |

No scenario passes because the agent produced plausible prose. It passes when
the experience, authority, owner, projection, consequence, and return all
agree.

## 3. Portfolio structure

The portfolio has two complementary suites.

### 3.1 Agentic-operation suite: A01–A12

These cases exercise entry compilation, cross-owner agency, permission,
consequence, correction, monitoring, and cross-root return.

### 3.2 Surface-and-compounding suite: A13–A18

These cases prevent the agentic harness from shrinking the product into a
travel operator with memory. They exercise unsolicited value, everyday
contribution, social enrichment, post-return re-entry, Life as an index, and
longitudinal compounding across all four roots.

Together the suites cover architecture breadth. Later bounded engineering
slices may implement portions of the portfolio, but no shipped slice is
allowed to redefine the ontology or the whole-product thesis.

## 5. Expanded whole-product experience requirements

### A01–A04: shaping without intake or container coercion

These cases jointly establish that the product can begin with a human job,
direct manipulation, an existing Home possibility, or contributed evidence.
It must not begin by forcing the person through intake or by creating a Trip.

Required experience properties:

- A first Chat turn performs real work with the authorized context already
  available.
- Direct selection in Places supplies nouns and scope; Chat supplies intent,
  explanation, and cross-owner composition.
- An ephemeral shape or route remains ephemeral until accepted.
- Home-to-Chat and Places-to-Chat entry preserves origin identity, selection,
  Moment, audience, authority, unresolved question, and return destination.
- Accepting a possibility promotes it through an explicit transition into a
  Plan, Occasion, Commitment, saved intention, or nothing.
- “For four” does not select three people, authorize contact, or create group
  state.

Primary unresolved rulings:

1. An Opening is not a durable owner. A03 should name an **Opening projection
   lineage** until an Occasion or Plan owns the accepted consequence.
2. A04 may replace a comparison with a route as the primary structured result,
   but it may not create two competing primary artifacts. Supersession must be
   explicit.
3. Availability must retain source, scope, freshness, and whether it is
   self-authored, shared, or provider-derived.

### A05: correction is a causal product behavior

The correction target is the smallest false relation, not the source file, UI
sentence, or entire episode. The system must:

- retain the photograph or Artifact under its custody rule;
- correct the owning Occurrence, Outcome, or relation;
- supersede the false Claim without rewriting history;
- invalidate dependent Home, Places, Life, generated, and social projections;
- preserve independently valid evidence;
- return one compact before/after receipt; and
- avoid teaching the person internal ontology.

The owner must be resolved more precisely than
`occurrence_or_outcome_relation` before implementation certification.

### A06–A10: the real-world engine

These cases establish a common engine across live local life, gatherings,
travel, commitments, providers, delivery, and monitoring:

```text
inspect -> compose -> propose -> commit -> monitor -> reconcile
```

The phases are runtime semantics, not a user-facing workflow.

Required experience properties:

- current constraints may affect a group-safe result without becoming shared
  explanation or durable personality evidence;
- Plan-edit, provider, spend, audience, and delivery authority remain
  independent;
- multi-owner requests expose verified, pending, failed, and not-attempted
  truth per owner;
- provider truth never derives from a Plan mutation;
- mandates remove redundant confirmation only inside their exact scope;
- monitors are durable, controllable jobs rather than promises in a transcript;
- Home shows material change or stable next step, not internal workflow; and
- Life later distinguishes intended, committed, occurred, and personally
  experienced state.

### A11–A12: explanation and novel synthesis

Vesper must expose the smallest causal set behind a selection and must add
substance beyond what the person already noticed.

Required experience properties:

- distinguish `You said`, `The record shows`, `Vesper inferred`, and
  `External sources report`;
- never answer with “your vibe” or an unsupported identity explanation;
- a question about selection does not become preference evidence;
- a Rome-to-New-York connection must add a new mechanism, contrast, analogue,
  route, or possibility rather than repeat “the Colosseum connects to the film
  you watched”;
- generated composition remains downstream of evidence and is not itself
  historical truth; and
- Home admits the result only if it has current value, not because generation
  succeeded.

### A13: quiet Home must still be valuable

**Situation.** The person is home in New York. Nothing is broken, no trip is
live, and no reflection task is pending. Vesper has authorized context from
recent travel, local life, friends, Places, Sources, and the coming weekend.

**Required composition.** Home returns a bounded field that may include:

- one genuinely new, evidence-grounded understanding;
- one timely local possibility with enough substance to enter immediately;
- one socially enriched contribution when another person's trace materially
  changes it;
- one practical state or capability that is useful before it becomes urgent;
- one restrained continuity door into Life; or
- fewer units, including silence, when candidates do not beat the attention
  threshold.

It does not lead with a prompt, unfinished thread count, trip report, generic
recommendation, capability tour, or “what do you want to remember?” question.

**Pass condition.** The person can receive value without contributing anything
and can ignore every unit without creating follow-up debt or inferred taste.

### A14: everyday contribution earns future context

**Situation.** The person sends something ordinary: a pasta photograph, a
restaurant receipt, a book passage, a movie ticket, a voice observation, or a
friend's message.

**Required sequence.** When the person deliberately Brings the material, Chat
first performs the immediate job: explain a
material difference, inspect evidence, compare with another grounded case,
identify a mechanism, prepare a practical use, or answer the stated question.
Only then may it quietly admit the smallest truthful Source-bound residue.

If the attachment accompanies an Ask, the default remains T0/no new durable
state. Transport does not determine gesture or retention.

Life makes the material re-findable without asking the person to categorize
it. Home or Places may use it later only when it changes a current
understanding, possibility, action, or return.

**Pass condition.** The contribution is useful in the moment and later reuse
is causally explainable. It does not become an identity claim, broad interest,
or organization chore.

### A15: asynchronous social value without a social feed

**Situation.** A friend in Paris contributes a Place, photograph, meal,
observation, or compact Status while the person is in Rome or later home in
New York.

**Required behavior.** The contribution appears only when it changes the
Place, comparison, possibility, Occasion, or understanding being rendered. It
retains author, audience, source precision, time, and use grant. The recipient
may receive a juxtaposition or borrowed idea without being asked to react.

The author's private original, the shared projection, the recipient's private
derivative, and any Occasion use are separate scopes. Withdrawal or precision
change recompiles them.

**Pass condition.** Social material makes the object richer without producing
an activity stream, response obligation, synthetic group meaning, or passive
live-location inference.

### A16: post-return re-entry is current-life-first

**Situation.** The person returns from Nice, Sorrento, Amalfi, and Rome to New
York. Vesper has tickets, routes, photographs, Places, food, notes, and social
context. The coming weekend and ordinary home life are already in motion.

**Required composition.** Home may factually reconstruct movement, compare
evidence, reveal an unnoticed recurrence, or connect the trip to a substantive
New York possibility. The trip is neither erased nor allowed to monopolize the
surface. A past element rises only when its current contribution is unusually
strong or changes what can happen next.

If cancellation recovery, compensation, rescheduling, delivery, or another
unfinished consequence remains active, that practical truth may outrank both
retrospective synthesis and a new possibility. Post-return is a changing
Moment, not a content genre.

Life owns the complete episode, source inspection, factual reconstruction, and
later return. Places owns spatial continuation and new local affordance.

**Pass condition.** Home makes returning feel like life is opening rather than
ending, while the factual record remains available without poetic personality
interpretation.

### A17: Life is an index over one identity system

**Situation.** The person vaguely remembers a dinner, wants to see where 2026
happened, or wants the shared material from one Occasion.

**Required behavior.** Life supports target-first search and reorganizes the
same owners through period, Timeline, Map, Artifacts/Sources, people, and
Occasion lenses. An `Around this` trail restores only the minimum context
needed to understand the result.

Planned-only, occurred, source-only, Mine, Together, disputed, revoked, and
unknown states remain distinguishable. Search reformulations do not become
durable interest evidence.

**Pass condition.** The person can find and understand the material without
maintaining folders, tags, or an AI-authored autobiography.

### A18: the compounding loop must prove causal reuse

**Situation.** An earlier contribution eventually changes a later answer,
Home unit, Place path, coordination decision, or appropriate silence.

**Possible complete sequence.** The richest fixture may span:

```text
Chat contribution
  -> immediate value
  -> minimum authorized Source/Claim residue in Life
  -> later Home or Places composition
  -> optional Plan/Occasion/Commitment consequence
  -> Occurrence and plural Outcomes
  -> later changed judgment, capability, or silence
```

No contribution is required to traverse every root. The later result must be
able to identify which evidence mattered, under what
scope, and why it is still fresh enough to use. Reuse does not upgrade
retention, audience, inference, or action authority.

**Pass condition.** The second occasion is materially better—less explanation,
better fit, faster coordination, safer delegation, a newly visible connection,
or a more appropriate decision not to intervene.

## 6. Root conformance requirements

### 6.1 Home — temporal composition

Home answers: **What is worth my attention now?**

It must:

- protect material consequences and affected people before editorial
  opportunity;
- admit at most one dominant foreground;
- complete the primary contribution in the compact projection;
- return value even when nothing is urgent;
- compose current, prospective, social, practical, and continuity value
  without quotas;
- rank by consequence, usefulness, novelty-to-person, receptivity, evidence,
  authority, and attention cost—not engagement probability;
- let a deeper Place, owner, or Life representation remain elsewhere; and
- allow every unit to end on view.

It must not become an archive, request inbox, trip recap, reflection surface,
generic recommendation feed, dashboard, capability gallery, or activity feed.

### 6.2 Chat — contribution and agency

Chat answers: **What do I want to give Vesper, understand, shape, change, or
cause?**

It must:

- remain visually sparse and capability-dense;
- accept multimodal contribution with minimal friction;
- deliver immediate value before requesting classification;
- preserve origin, selection, audience, authority, and return context;
- inspect, compose, propose, commit, monitor, reconcile, and repair through
  canonical owners;
- return one primary answer or structured result and only necessary receipts;
- expose owner truth and uncertainty rather than tool execution theater; and
- allow direct UI and language to manipulate the same typed state.

It must not become an intake-only collector, discovery feed, universal
database, transcript-as-Life, or duplicate UI for every domain.

### 6.3 Places — spatial composition

Places answers: **What does the world afford me here, now, or next—and why?**

It must:

- converge search, map, selection, paths, Home handoffs, and Chat operations on
  one semantic Place state;
- combine world identity, current affordance, personal relationship, human
  perspective, and sparse horizon paths as needed;
- distinguish stable Place truth from provider truth and current conditions;
- reveal why a Place appears without inventing biography;
- integrate attributed social evidence only when it changes the Place or
  possibility;
- preserve selection and viewport through comparison and route operations;
- support World Field, Place Focus, Place Path, and Live Reduction without
  turning those into four permanent content modules; and
- return value before asking the person to save, plan, or refine.

It must not become a ranked section feed, generic map, venue directory,
recommendation list, raw graph, permanent lens taxonomy, friend-activity feed,
or save repository.

### 6.4 Life — continuity and organization

Life answers: **What exists in my Vesper world, where does it belong, and what
remains true and usable?**

It must:

- use a period-and-episode spine with contextual lenses;
- preserve the identity, provenance, authorship, audience, represented time,
  revision, and correction path of Sources and owners;
- support Find, Return, See anew, and Continue;
- distinguish planned, occurred, captured, authored, generated, disputed, and
  unknown state;
- provide target-first re-finding and bounded context reconstruction;
- preserve plural shared history with viewer-relative access;
- route correction and deletion through canonical owners; and
- keep dynamic Returns subordinate to the stable record.

It must not become a second Home, task queue, archive dump, universal card
library, personality dossier, scrapbook, nostalgia feed, or organization
homework.

## 7. Cross-root handoff and return contract

Every meaningful handoff must carry:

- origin root and object;
- selected `ResourceRef` identities and revisions;
- immediate job;
- viewer and audience scope;
- contribution grant reference;
- agency ceiling and authority source;
- current Moment and freshness;
- unresolved question, decision, or consequence;
- target owner or capability;
- return destination and presentation mode;
- expiry, correction, and causal lineage where applicable.

### Recommended navigation ruling

1. **Inspect depth from Home or Places:** open an overlay or pushed owner view;
   Back returns to exact scroll, map viewport, selection, and composition
   revision when still valid.
2. **Continue in Chat:** Chat receives a typed entry, not reconstructed prose.
   Terminal results offer `Return to [origin]` or `Open [owner]`.
3. **Explicit root switch:** enter that root's stable workspace posture rather
   than replaying a stale overlay.
4. **Background completion:** material updates appear in Home or Push according
   to delivery policy; opening them targets the owner or active instrument,
   with Chat available for explanation.
5. **Stale origin:** preserve object identity and explain that the prior
   composition changed; never return to a visually similar but semantically
   different card.

## 9. Authority normalization

### 9.1 One policy model

The contribution contract's five axes remain normative:

| Canonical axis | More specific questions it contains |
| --- | --- |
| Use | may this material be used for the current job, later job, or named purpose? |
| Retention | may the Source, Claim, mandate, or result persist, for how long and under which lifecycle? |
| Inference | what may be inferred, at what target and epistemic level? |
| Audience | who may see it, be named, be contacted, or receive a derived projection? |
| Action | what may be prepared, proposed, committed, monitored, undone, or delegated? |

`may-name`, `may-contact`, and `may-show` are audience subpermissions, not a
second policy system. Scope, authority source, mandate reference, affected
principals, threshold, expiry, and protected consequence belong in typed
fields—not ad hoc enum values.

### 9.2 Fixture schema corrections

Before fixtures become executable contracts, normalize:

- `source_bound_private` -> retention `source_bound` plus private scope;
- `group_safe_effect_only` -> Occasion audience plus minimum-safe projection
  policy;
- `named_occasion` and `affected_participants` -> audience scope and affected
  principal refs;
- `commit_requested`, `existing_mandate`, and `monitor_mandate` -> action mode
  plus explicit authority-source/mandate refs; and
- `monitor_scope` and `threshold_only` -> retention/inference base modes plus
  monitor scope, threshold, and expiry fields.

## 11. Resolved product decisions

All rulings below are accepted by
`2026-08-29-close-whole-product-v1-wave-0.md`. They are no longer a proposal
queue. Detailed visual composition and ranking calibration remain experimental.

| Decision | Recommendation | Why |
| --- | --- | --- |
| Four-root authority status | Accept as target product canon; keep visual anatomy experimental | The orientation system is coherent across the portfolio; uncertainty is composition, not navigation purpose |
| Opening ownership | Keep Opening ephemeral by default | Persist accepted intention, Plan, Occasion, Commitment, or Outcome—not every possibility |
| Opening promotion | Require explicit or owner-authorized transition with source lineage | Prevents Home ranking output from silently becoming intent or planning state |
| Generated composition lifecycle | Ephemeral by default; saved/shared compositions receive versioned manifest identity | Avoids both disposable output and generated prose becoming historical truth |
| Episode fallback | A Life episode remains a projection unless a Journey, Occasion, or other owner passes eligibility gates | Avoids universal episode tables while preserving re-finding |
| Permission vocabulary | Five axes are canonical; narrower permissions are typed subfields | Prevents two incompatible policy systems |
| Direct UI vs Chat | Direct UI for one visible low-risk operation; Chat for ambiguity, composition, explanation, cross-owner work, monitoring, and repair | Preserves fluidity without hiding complexity or making Chat mandatory |
| Life vs settings | Life owns contextual inspection/correction; account settings own global connectors, mandates, export, and destructive scope | Keeps Life human and contextual while global policy remains discoverable |
| Home vs Places ranking | `why now` foregrounds on Home; `why here/there` owns depth in Places | Avoids duplicate feeds while allowing the same object to project into both |
| Social material | Admit only when it changes the object, possibility, participation, or coordination | Creates multiplayer value without an activity feed |
| Monitor implementation | Define now; build after semantic reads and command authority are stable | The engine must be coherent now, but a new durable job should not precede owner semantics |
| Trip migration | Keep proven writers behind adapters until general owners demonstrate parity | Preserves operational guarantees while changing the agent's worldview |

## 13. Verification portfolio

### 13.1 Product conformance

- value appears before input, classification, reflection, or organization;
- every unit has one dominant job;
- roots mix the four moves unevenly rather than acting as move containers;
- ordinary life and post-return life are first-class;
- the engine is legible beyond live travel;
- social material enriches objects and consequences rather than producing feed
  pressure;
- every experience may stop cleanly.

### 13.2 Architecture conformance

- one identity and revision travel across roots;
- canonical owners retain mutations;
- projections remain recomputable unless deliberately saved/shared;
- authority never expands through confidence, inference, reuse, or tool choice;
- provider, Plan, Commitment, Occurrence, and Outcome truth remain distinct;
- correction and revocation propagate causally;
- missing owner support remains `unavailable`, not semantically faked.

### 13.3 Surface conformance

- Home is valuable without a prompt;
- Chat is calm without becoming shallow;
- Places is more than map/search/recommendation;
- Life is usable without ontology maintenance;
- cross-root handoff preserves context and return;
- one page has a coherent attention hierarchy and bounded demand;
- medium follows the cognitive or practical job, not renderer novelty.

### 13.4 Runtime conformance before dogfooding

Dogfooding does not begin until:

- the four-root shell and navigation are structurally stable;
- object persistence, readback, correction, and deletion work;
- contribution permissions and audience behavior are understandable;
- Home and Places consistently return substantive value;
- Chat can explain what it did and where the result lives;
- Life can recover relevant history without classification work;
- multiplayer authorship, visibility, and withdrawal are safe;
- routine surface changes no longer invalidate the experience under
  evaluation; and
- runtime telemetry has a named decision it can answer.

Until then, use deterministic fixtures, owner-read parity, design reviews,
content evaluation, and architecture conformance—not behavioral claims.

## 15. Stop conditions

Pause and revise the product contract if:

- a complete experience repeatedly needs a fifth durable human orientation;
- Home and Places cannot be distinguished without arbitrary content rules;
- Life requires people to curate an ontology to remain useful;
- Chat must duplicate every owner UI to complete cross-owner work;
- multiplayer value requires a generic activity feed;
- an ephemeral projection repeatedly needs hidden durable authority;
- a new universal object is proposed without at least three portfolio cases and
  a correction/ownership argument; or
- one implementation slice starts defining the whole product model merely
  because it shipped first.

## Compact standard

> Design the complete lived-world portfolio together. Let each bounded
> implementation slice serve that portfolio without becoming the product.
> Return value before asking for work; preserve one owner per consequence; let
> the four roots remain different views of one governed world.
